## Принцип работы

Реализует вариант **In-Context Vectors (ICV)**, в котором информация о задаче, задаваемой контекстом, используется не через добавление демонстраций в промпт, а через **модификацию логитов** при генерации ответа.

Высокоуровнево:

- сначала модель прогоняет **контекст** через LLM и извлекает распределение по токенам (топ‑логиты/логпробности);
- на основе этого распределения формируется словарь `token_id → delta`, который кодируется в строку и передаётся на сервер `vllm` в дополнительных аргументах запроса;
- на сервере специальный `LogitsProcessor` (см. ветку `project/icv_logit_processor`) парсит эти аргументы и **добавляет соответствующие сдвиги к логитам** при генерации ответа на основной запрос;
- таким образом контекст влияет на то, какие токены модель предпочитает в ответе, не занимая место в контекстном окне и не требуя финетюнинга.

В отличие от оригинальной статьи, где ICV прибавляется к латентным представлениям слоёв трансформера, в данной реализации сдвиг реализуется **на уровне выходных логитов** через кастомный логит‑процессор в `vllm`.

---

## Параметры инициализации

- `url: str` — базовый URL OpenAI‑совместимого API (`vllm`‑сервер); используется и для обычных запросов, и для вспомогательного эндпоинта токенизации.
- `model_name: str` — имя модели, по которой выполняются:
  - вычисление логпробностей по контексту,
  - генерация ответа с применением логит‑сдвигов.
- `weight: float = 1.0` — коэффициент, с которым передаётся информация о логит‑сдвигах в логит‑процессор; позволяет усиливать или ослаблять влияние ICV на ответ.

## Алгоритм

Метод `ICV.run(task: Text, context: Text)` выполняет следующие шаги.

### 1. Оценка контекста и построение "вектора" влияния

1. Вызов `_eval_example(context: Text)`:
   - выполняется запрос `completions.create` с параметрами:
     - `model=self.model_name`,
     - `prompt=context`,
     - `temperature=0`,
     - `max_tokens=1`,
     - `logprobs=20`.
   - из ответа берётся `top_logprobs` для следующего токена: словарь `token_str → logprob`.
2. `_get_token_ids(tokens: list[str])`:
   - для каждого строкового токена выполняется POST‑запрос к вспомогательному эндпоинту `/tokenize` на том же `vllm`‑сервере;
   - полученные ID первого токена в ответе собираются в список `token_ids`.
3. Результат `_eval_example` — словарь `{token_id: token_logprob}` для топ‑токенов по контексту.
4. Формирование полезной нагрузки для логит‑процессора:
   - конструируется строка формата  
     `"<token_id1>:<logprob1>;<token_id2>:<logprob2>;..."`;
   - создаётся словарь:
     - `icv_load = {"target_tokens": <строка>, "weight": self.weight}`.

### 2. Генерация ответа с применением логит‑сдвигов

1. Вызывается `chat.completions.create`:
   - `model=self.model_name`,
   - `messages=[{"role": "user", "content": task}]`,
   - `temperature=0`,
   - `extra_body={"vllm_xargs": icv_load}`.
2. На стороне сервера:
   - `vllm` пробрасывает `vllm_xargs` в параметры сэмплирования (`SamplingParams.extra_args`);
   - кастомный `ICVLogitProcessor`:
     - парсит строку `target_tokens` в словарь `{token_id: delta}`,
     - при каждом шаге генерации **добавляет `delta` к логиту соответствующего токена** для данного запроса;
     - масштабирует влияние с учётом `weight`.
3. В итоге токены, которым модель присваивала высокую вероятность по контексту, получают положительный сдвиг логитов и становятся более предпочтительными при генерации ответа для `task`.

4. Агент возвращает `response.choices[0].message.content` как итоговый текстовый ответ.

## Замечания

- **Источник информации**: как и в статье, задача задаётся демонстрационным контекстом, который сначала отдельно пропускается через модель.
- **Где применяется сдвиг**:
  - в оригинальной работе ICV прибавляется к скрытым состояниям (latent states) слоёв трансформера;
  - здесь сдвиг реализуется на уровне **логитов выходного слоя** через логит‑процессор `vllm`.
- **Контроль силы эффекта**:
  - вместо прямого масштабирования вектора в латентном пространстве сила влияния управляется параметром `weight`, задающим масштаб логит‑сдвигов.

Такой подход сохраняет ключевую идею ICV — **разделение этапов "извлечь информацию из контекста" и "применить её при ответе"**, но адаптирует её к инфраструктуре `vllm` через модификацию логитов.
