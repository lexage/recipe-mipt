## Принцип работы

Реализует метод **LENS (fiLter-thEN-Search)** для выбора и упорядочивания поддерживающих примеров в in-context learning.  
Работа разбита на две стадии:

1. **Фильтрация (informative examples filtering)** — из исходного пула примеров отбираются индивидуально информативные, используя метрику, аналогичную **InfoScore** из статьи (измеряет, насколько пример помогает языковой модели лучше классифицировать другие примеры).
2. **Поиск (diversity-guided example search)** — над отфильтрованными примерами выполняется поиск перестановки фиксированного размера, которая одновременно:
   - максимально информативна (по InfoScore-подобной метрике),
   - достаточно разнообразна (минимизирует избыточное сходство примеров).

На выходе блок возвращает подмножество/перестановку входных `Chunk`, которые рекомендуется использовать как демонстрации в промпте для ICL.

## Параметры инициализации

- `model_name: str` — имя LLM, через которое считается перплексия и InfoScore-подобный скор.
- `url: str` — `base_url` для совместимого OpenAI-совместимого API (в проекте ожидается локальный `vllm`‑сервер).
- `embedding_model: Agent` — агент, возвращающий векторы признаков примера (используется для оценки разнообразия; если `None`, диверсификация происходит случайно).
- `filtered_set_size: int` — желаемый размер множества информативных примеров после стадии фильтрации.
- `search_set_size: int` — количество примеров в одной искомой перестановке (число примеров, которые в итоге будут выбраны для ICL).
- `search_iterations: int` — число итераций поиска по пространству перестановок.
- `diversity_weight: float` — коэффициент \(\lambda\) перед штрафом за сходство примеров; регулирует баланс "информативность vs разнообразие".
- `progressive_factor: int` — прогрессивный коэффициент \(\rho\) из статьи; задаёт, во сколько раз на каждой итерации сужается множество кандидатов.
- `init_score_set_size: int` — размер начального множества `score_set`, по которому считается InfoScore-подобный скор в фильтрации.
- `beam_size: int` — размер бима во второй стадии (количество одновременно поддерживаемых перестановок).
- `substitution_size: int` — число диверсифицирующих замен в каждой перестановке на итерацию поиска.

## Алгоритм

Для выбора примеров вызывается метод `Lens.apply(chunks: List[Chunk])`:

1. **Подготовка входа**
   - Формируется отображение `text -> Chunk` и список текстов `chunks_text`.

2. **Стадия фильтрации (`filter`)**
   - Инициализируется `score_set` случайным подмножеством примеров размера `init_score_set_size`.
   - Пока размер множества информативных примеров превышает `filtered_set_size`:
     - Для каждого кандидата считается информационный скор `self._info_score(example, relative_set=score_set)`, завязанный на перплексию LLM:
       - считаем перплексию примера `re` без контекста `example`;
       - считаем перплексию `re` с добавленным контекстом `example`;
       - разность перплексий суммируется по всем `re` из `score_set`.
     - Оставляются только топ‑примеров:
       - либо до целевого размера `candidate_size`,
       - либо промежуточно — уменьшение размера в `progressive_factor` раз.
     - В `score_set` добавляется случайное подмножество примеров, чтобы уточнить оценку InfoScore на следующих итерациях.
   - Результат стадии — список `informative_examples` и финальный `score_set`, сохраняемый в `self.score_set`.

3. **Стадия поиска (`search`)**
   - Генерируется начальный пул перестановок длины `search_set_size` с помощью `self._get_permutations` (случайная выборка примеров).
   - По `search_iterations` раз повторяется:
     - Для каждой текущей перестановки:
       - **Substitution phase**: `substitution_size` раз:
         - случайным образом выбирается пример из перестановки;
         - по функции `self._diversity(example, example_set=...)` подбирается новый пример из `informative_examples`, который:
           - информативен (InfoScore по `self.score_set`),
           - и при этом как можно менее похож на уже выбранные (по косинусному сходству эмбеддингов, если задан `embedding_model`).
         - полученная модифицированная перестановка добавляется в пул кандидатов.
       - **Random permutations**: дополнительно генерируются случайные перестановки из тех же примеров, чтобы расширить поиск.
     - Кандидаты проходят через `_eval`, которая должна ранжировать перестановки по качеству на валидационном множестве (в текущем коде — заглушка, берущая первые `beam_size`).
   - Возвращается лучшая (по текущей реализации — первая) перестановка.

4. **Формирование результата**
   - Тексты из найденной лучшей перестановки сопоставляются обратно с исходными `Chunk`.
   - Возвращается список `Chunk` в найденном порядке — его и следует использовать как демонстрации при формировании промпта для ICL.

## Замечания

- **Кеширование перплексий** (`_ppl_cache`) и эмбеддингов (`_examples_features_cache`) реализовано для снижения числа обращений к LLM и `embedding_model`.
- При `embedding_model is None` диверсификация частично подменяется случайностью, поэтому качество второй стадии может отличаться от оригинальной реализации.
- Поскольку метод полагается на LLM‑перплексию для InfoScore, вычислительная стоимость растёт с размером обучающего множества.
