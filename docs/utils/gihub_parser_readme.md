# GitHub Repository Parser

- **Модуль**: [`github_parser`](../../src/utils/github_parser)
- **Точка входа**: [`main.py`](../../src/utils/github_parser/__main__.py)
- **Основные компоненты**: 
  - [`TorchGitHubLoader`](../../src/utils/github_parser/github_repo_loader.py) - модуль загрузки файлов c выбранного GitHub-репозитория.
  - [`CSTCodeParser`](../../src/utils/github_parser/cst_parser.py) - парсинг кода на языке программирования Python из загруженных файлов.
  - [`DatasetBuilder`](../../src/utils/github_parser/dataset_builder.py) - сборка датасета для загрузки в базу данных.

---

## Принцип работы

Инструмент предназначен для автоматического создания датасета пар «описание задачи - код решения» на основе исходного кода GitHub-репозиториев. 

Процесс включает в себя рекурсивный обход репозитория через GitHub API, фильтрацию файлов и синтаксический анализ Python-кода с использованием библиотеки **LibCST**. Основная логика заключается в извлечении примеров использования (examples) из Docstring-ов классов и функций.

Высокоуровнево:
1. Загрузчик скачивает содержимое файлов, соответствующих заданным критериям (расширения, исключения).
2. Парсер строит абстрактное синтаксическое дерево.
3. Кастомный визитор (`DocstringProcessor`) находит классы и функции, анализирует их документацию.
4. Если в документации найдены ключевые слова (например, `Example:`, `>>>`), текст разделяется на описание задачи, код решения и библиографические ссылки.
5. Результат сохраняется в структурированном виде (`ExtractedExample`).

---

## Конфигурация и инициализация

Конфигурация задается через YAML-файл, который распаковывается в объект `GitHubExampleFetcherConfig`.

### Основные параметры (`GitHubExampleFetcherConfig`)
- `repo_for_analyzing: str` — идентификатор репозитория (формат `owner/repo`).
- `specific_folder_for_analyzing: str` - путь к конкретной папке или файлу для анализа (опционально). Если указана пустая строка, будет проанализирован весь репозиторий.
- `config_for_github_loader: GitHubLoaderConfig` - настройки загрузчика файлов.

### Настройки загрузчика (`GitHubLoaderConfig`)
- `allowed_file_extensions: Tuple[str, ...]` - расширения для обработки (по умолчанию: `.py`, `.md`, `.rst`).
- `skip_file_patterns: Tuple[str, ...]` - подстроки в пути файла для пропуска (по умолчанию: `init`, `test`).

### Инициализация пайплайна (`DatasetBuilder`)
Для работы сборщика датасета требуются экземпляры загрузчика и парсера:

- `loader: TorchGitHubLoader` - клиент GitHub API. Требует токен доступа (переменная окружения `GITHUB_ACCESS_TOKEN`).
- `parser: CSTCodeParser` - инструмент анализа AST.

---

## Алгоритм

Процесс запускается методом `DatasetBuilder.run(target_repo, target_folder)`, который выполняет следующие шаги:

### 1. Обход репозитория (`TorchGitHubLoader`)
1. Устанавливается соединение с репозиторием через `PyGithub`.
2. Скачивается `README.md` (если есть).
3. Рекурсивно обходится файловая структура. Файлы фильтруются:
   - Исключаются файлы, содержащие паттерны из `skip_file_patterns` (например, тесты).
   - Оставляются только файлы с расширениями из `allowed_file_extensions`.
4. Возвращается итератор объектов `RepoFile`. Каждый объект содержит путь и байтовое содержимое файла.

### 2. Парсинг кода (`CSTCodeParser`)
Для каждого Python-файла:
1. Строится дерево CST (`libcst.parse_module`).
2. Запускается `DocstringProcessor` (наследник `cst.CSTVisitor`), который посещает узлы `ClassDef` и `FunctionDef`.
3. Извлекается docstring узла и анализируется методом `_process_docstring_text`:
   - Ищется раздел примеров по ключевым словам: `Example:`, `Examples:`, `Example (description):` или наличие REPL-символов `>>>`.
   - Текст до примера интерпретируется как **Task Description**.
   - Текст после заголовка примера — как **Solution Code**.
   - Код очищается от символов `>>>` и `...`.
   - Отдельно парсится раздел `References:` для извлечения ссылок на научные работы.
4. Сохраняется исходный код всего объекта (`metadata_source_code`).

### 3. Формирование результата
На выходе формируется список объектов `ExtractedExample`, содержащий:
- `source_object_type`: тип (функция или класс).
- `source_object_name`: имя объекта.
- `task_description`: описание задачи.
- `solution_code`: чистый код примера.
- `metadata_source_code`: полный исходный код объекта.
- `references`: найденные ссылки.

---

## Замечания

- **Токен доступа**: Для работы необходим `GITHUB_ACCESS_TOKEN` в файле `.env`.
- **Эвристики парсинга**: Разделение докстринга основано на регулярных выражениях. Поддерживаются форматы Google-style docstrings, Sphinx-style и простые блоки с `>>>`.
