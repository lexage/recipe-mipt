## Устройство пайплайна (текущая конфигурация экспериментов)

Семантический RAG: `LOCAL_DB` (sqlite + Qdrant) → `RECURSIVE_CHUNKER` (1000)
→ `SIMPLE_RETRIEVER` (top_k=5) + `QUERY_GENERATOR`-энхансер →
`CORAG_CONTEXT_ASSEMBLER` → `DS1000_SOLVER_AGENT`. Слот `generator`
(опционально) — на этапе билда порождает документы в индекс
(`keep_source_docs: True`).

- БД: `data/docs_database_examples.db` — 18 063 документа (документация 7
  библиотек, маркеры `<example_N>`) + 45 867 код-примеров в таблице
  `examples`. `merge_examples: True` вклеивает примеры в текст дока.
- Ручные базы: `data/docs_database_examples_aug.db` (оригинал + 197 ручных
  доков, «v1») и `..._aug_v2.db` (v1 + 38, «v2» — признана незначимой,
  не используем).
- Свежий `path_to_vector_db` на каждый конфиг (vector-db-reuse bug!).

### Генераторы (src/generation/)

- `rag_guides.py` / `RAG_GUIDE_GENERATOR` — инструкционный метод (после
  редизайна exp14): стадии A (инструкции поведения), T (инструкции по
  типовым вопросам, темы перечисляет LLM), B (миграция API из зашитого
  чек-листа 42 семейств). Ручка `policy: v1|v2` (v2 = Q&A-миграции,
  обязательный `result = ...`, углы def f). Аудит-дамп в
  `results/gen_dumps/*.jsonl`, счётчики выхода в лог.
- `api_guides.py` / `API_GUIDE_GENERATOR` — API-якорный метод (exp15):
  регекс-перепись API по коду корпуса → топ-150 частотных → инструкция на
  каждый API с токеном в заголовке и теле (лексический якорь для ретрива).
- Регистрация — `src/pipelines/constants.py`; НЕ использовать
  `from __future__ import annotations` в файлах с Block-зависимостями.

### Анализ ошибок (локально, venv)

Классификатор и дампы: `results/error_analysis_exp8/analyze_failures.py`
(джойн ds1000 + answers + results, автокластеры по сигнатурам ошибок).
Поведенческие маркеры, вычисляемые по answers.jsonl: redef-rate (доля

писать в scratchpad-файл и запускать по /mnt/c-пути с `PYTHONPATH=.`.

## Правила добавления нового

- **Новый генератор**: класс в `src/generation/<имя>.py` (наследовать
  `Generator` или `RagGuideGenerator` — у него готовые `_run_jobs`,
  `_parse_doc`, `_package` с валидацией AST/длина/дедуп и дампом),
  регистрация в `constants.py`, конфиг в новой папке эксперимента.
- **Новый эксперимент**: `test_configs_experimental_<N+1>/`, имена конфигов
  уникальные (результаты ложатся в `results/<stem>/<timestamp>/`), свежие
  vdb-пути, эндпоинты 7114/7216.
- В генерации ЗАПРЕЩЕНО использовать что-либо из DS1000; в инструкциях
  нельзя упоминать маркеры обвязки (`BEGIN SOLUTION` и т.п. — даже в коде
  метода их быть не должно).
